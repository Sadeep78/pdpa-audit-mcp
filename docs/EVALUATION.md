# Real-World Accuracy Evaluation

This document records empirical evaluation results of `pdpa-audit-mcp` across real-world Sri Lankan and global production websites, staging environments, and open-source repositories.

> [!NOTE]
> The automated test suite (`tests/test_rule_matrix.py`) is a regression harness on synthetic text and markup samples to prevent regressions. Real-world accuracy (precision, recall, and false positive/negative rates) is evaluated through manual review against ground truth using evaluation sheets generated by `scripts/evaluate.py`.

## Human Verdict Definitions

When reviewing audited targets against the checklist criteria aligned with Sri Lanka's Personal Data Protection Act No. 9 of 2022, human evaluators record one of four verdicts per rule finding:

1. **`correct`**:
   The tool's determination matches ground truth reality:
   - Tool reported `passed`, and the requirement is demonstrably satisfied by the target.
   - Tool reported `failed`, and a gap against the checklist is indeed present in the audited content.

2. **`false pass`**:
   The tool reported `passed`, but the underlying legal or technical requirement is **NOT** satisfied in reality (e.g. an indicator keyword matched in an unrelated context, or an incomplete policy clause passed regex checks).

3. **`false fail`**:
   The tool reported `failed`, but the underlying requirement **IS** satisfied in reality (e.g. the policy uses non-standard phrasing not in the indicator dictionary, or cross-border processing disclosures are hosted on a separate sub-page).

4. **`n/a`**:
   The rule is not applicable to this target (e.g. no cookies set, no password fields, no external vendors, no web forms), or the requirement cannot be assessed statically.

> [!TIP]
> Findings flagged with `needs_review` or `not_evaluated` are handled separately as items requiring human judgment or unassessed tools; they do not count against binary pass/fail precision or recall metrics.

## Evaluation CLI Tool

To generate a new evaluation labeling sheet for an authorized target:

```bash
python scripts/evaluate.py --url https://your-site.lk --confirm-authorised --out docs/evaluation_sheet.md
```

Options:
- `--url URL`: Target website URL to audit.
- `--project PATH`: Optional local repository directory.
- `--confirm-authorised`: Explicit confirmation that you own or are authorised to audit the target (refuses to run without this flag).
- `--out PATH`: Destination path for the generated Markdown sheet (default: `docs/evaluation_sheet.md`).

## Methodology

1. **Target Selection**: Diverse collection of Sri Lankan public and private websites (commercial, e-commerce, banking, public service) and application codebases that the audit team is authorized to evaluate.
2. **Automated Audit**: Execute `scripts/evaluate.py` to produce a rule-by-rule sheet with tool status, matched terms, and evidence snippets.
3. **Independent Human Review**: Two reviewers independently examine the site and code against the official gazetted Act.
4. **Scoring**: Compute binary precision, recall, false pass rate, and false fail rate across all evaluated targets.
